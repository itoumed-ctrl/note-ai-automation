# GitHub・Canva・Claude Codeの3つをつないだ記録。接続で確認したこと5つ

## 前回のおさらいと今回の範囲

こんにちは。31歳、AI初心者のまま勉強しながら進めている筆者です。「AI自動化の実録」シリーズの第2回です。

前回は、noteを「完全自動」にせず、「下書きまで自動、公開は人間が予約投稿」という半自動にした理由を書きました。今回は、その仕組みの土台になる3つ、GitHub・Canva・Claude Codeを実際につないだ記録です。

先に現在地をお伝えします。2026年11月16日時点で、公開したnote記事は0本、有料記事の売上は0円です。前回の記事（第1回）は、noteに下書きとして入れたところまで進んでいて、公開はまだしていません。

この記事で書くのは、実際に動かして確認できたことだけです。うまくいった話だけでなく、403エラーや、真っ白な画像が出てきた話もそのまま書きます。

この記事の本文は、前回と同じくAI（Claude Code）が下書きを書き、AI秘書のMuseが事実確認をして、最終確認は人間である私が行っています。

## なぜGitHubを真ん中に置いたのか

2026年11月15日に、進め方を次のように決めました。

> GitHubを真ん中に置く。1タスク＝1ブランチ＝1PR。マージは人間が判断する。

Claude Codeが書いた原稿も、Museが確認した内容も、いったんGitHubのリポジトリに集めます。何を変えたのかが履歴に残りますし、AIが書いたものを人間がレビューしてから取り込む、という流れも作れます。「AIに丸投げしない」という方針を、仕組みの形にしやすいと考えました。

なお、他の案と比べて選んだ、というところまでは記録していません。この決定は「こうしよう」と決めたもの、というのが正直なところです。

## 接続1：GitHub

2026年11月16日、GitHubをOAuthで接続しました。アカウントは私のものです。接続そのものは、ここまでは順調でした。

ところが、次のステップで壁にぶつかりました。

- コネクタ経由でリポジトリを作ろうとすると、403エラーになり、作成できなかった
- そこで、リポジトリは人間（私）が手動で作成し、GitHub Appのインストール対象に追加した
- 最初のpushも、インストールが済むまでは403で失敗した
- インストール後は、土台となるファイル4点をpushできた（commit 719a025）

「接続できた」と「何でもできる」は別のことでした。この点は、あとで「確認したこと」としてまとめます。

画像（接続完了画面のスクリーンショット）は撮っていないので、この記事には載せていません。

## 接続2：Canva

Canvaは、記事のアイキャッチ画像を作るために接続しました。実際にアイキャッチの作成が通ったことは確認できています。

ただし、一発で思いどおりにはいきませんでした。

- 1枚目は正方形（1264×1264）で出てきたため、note推奨の1280×670にリサイズした
- 色の方向性は、私の希望で2回変わった（白×紺×ティール → 深緑×ゴールド×ピンク → 白×薄グレー×青）
- 生成結果が真っ白になった回があり、作り直した
- Canvaの無料リサイズの枠を使い切ったため、最後は原寸で書き出し、ローカルで1280×670に切り抜いた
- 最終版は、見出しを小さめにして余白を広げたものに落ち着いた

「つながった」というより、「つないだ先で、出てきたものを見ながら手直しした」というのが実態です。

## 接続3：Claude Code ↔ リポジトリ

2026年11月16日、Claude Codeを、Museの環境の中にインストールしました（CLI 2.1.325）。Claude Proのアカウントで使っていて、モデルはSonnetを指定しています。これは人間である私の指示です。

ログインで、最初の小さなつまずきがありました。OAuthログインのリンクが最初は開けず、私がブラウザでログインして、表示された認証コードを貼り付ける形で完了しました。

その後のスモークテスト（動くかどうかの簡単な確認）で、接続OKを確認できました。

そして、PRの運用が実際に回りました。

- PR #1：シリーズの構成案 → マージ
- PR #2：第1回の本文 → マージ
- PR #3：STYLE.md（口調や表記のルール）と方向性の改稿 → マージ

マージの判断は、3つとも私が行いました。「1タスク＝1ブランチ＝1PR、マージは人間」という決め事が、少なくとも3回は動いたことになります。

## 接続で確認したこと5つ

ここからが本題です。3つをつないだ中で、実際に起きたことから確認できたことを5つにまとめます。

### 1. 権限まわりは、最初に詰まる

「つながった」と思っても、リポジトリの作成とpushは別の権限でした。コネクタ経由のリポジトリ作成は403で、最初のpushもGitHub Appのインストールが済むまで403でした。

解決は、人間がリポジトリを手動で作り、インストール対象に追加することでした。AIにお任せする前に、どこまでの権限を渡すかを確認しておくと、迷う時間が減りそうです。

### 2. ログインは、人間の手が必要になる場面がある

Claude CodeのOAuthログインは、リンクが開けず、私がブラウザでログインして認証コードを貼り付けました。note側も、第1回の下書きを入れるときのログインは人間の担当です。

「全部をAIに」ではなく、「ログインは人間」と最初から分けておくほうが、自然に回ると感じました。これは前回決めた半自動の考え方とも合っています。

### 3. 出てきたものは、サイズと中身を目で確認する

Canvaの1枚目は1264×1264の正方形でした。note推奨の1280×670に合わせる作業が必要でした。生成が真っ白になった回もありました。

noteへの入稿でも似たことがありました。第1回の記事をブラウザ操作で下書きまで入れたところ、Markdownの多くは変換されましたが、太字の「**」が2か所だけ文字として残っていて、手直ししました。差し替えのときにも同じことが再発しました。

AIが作ったものは、サイズも、中身も、変換後の見た目も、人間が最後に見る。この確認は省けないと思いました。

### 4. 無料枠や回数の制限は、途中で出てくる

Canvaの無料リサイズ枠を使い切って、最後は原寸で書き出し、ローカルで切り抜きました。作業が止まったわけではありませんが、道具の使い方を変える必要がありました。

使う前に、枠や制限を確認しておくこと。そして、枠を使い切っても別の手段（今回は手元での切り抜き）がある状態にしておくこと。この2つを意識したいと思います。

### 5. PR運用は回る。ただし、判断は人間が持つ

PR #1から#3まで、「書く→PRを出す→人間がマージを判断する」の流れが実際に回りました。AIが書いたものが、人間の確認なしに取り込まれることはありません。

回ることが確認できたのは3回分です。大量の記事を回したときにどうなるかは、まだ試していません。
