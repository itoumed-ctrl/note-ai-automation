# Claude Haiku 5.5の実務的な学び3つ

## 先に、お断りしておきます

こんにちは。31歳、子育て中の父親で、AI初心者の筆者です。本業でAIを使えるようになりたくて、勉強しながらnoteの運営をAIと一緒に進めています。

この記事は「AIニュース勉強ノート」の第7回です。大きなAIニュースが出たときに、初心者の僕が公式発表を読んで、勉強しながら理解していくシリーズです。速報でも専門家の解説でもなく、「初心者はこう読んで、こう考えました」の記録です。

今回は、Anthropicが2026年10月7日に発表した小型モデル「Claude Haiku 5.5」を読みます。最新ニュースではありませんが、「量のある定型作業を、どのモデルに任せるか」という実務の話に直結していたので取り上げます。最初に、立場をはっきりさせておきます。

- 僕は Claude Pro を契約していて、Claude Code を使っています。開発のメインは Sonnet を指定しています
- **Haiku（現行の 5.5）は、日常的に使っています。** 「めちゃくちゃ使っている」と言えるくらいです。用途は、要約や照合のような定型処理、日常の調べもの、Web操作などです
- この記事は、製品や乗り換えをすすめるものではありません。あくまで勉強ノートです

書いてあるのは、公式発表を読んで僕が理解できたことと考えたこと、そして僕自身の使い方だけです。記事の下書きはAI（Claude Code）が書き、AI秘書のMuseが事実確認をして、最終確認は人間の僕が行っています。

**この記事でわかること**

- Claude Haiku 5.5の公式発表に、何が書かれていたか
- 「安い＝弱い」ではなくなり、モデルは作業で使い分けるものになってきたこと
- コストが下がっているのは、モデル本体だけではないこと

## ① 何が出たのか

Anthropicは2026年10月7日、公式発表「Introducing Claude Haiku 5.5」で、小型モデルの Claude Haiku 5.5 を発表しました。公式の表現では、「これまでで最も安く、最も速く、最も高性能な小型モデル」です。API名は `claude-haiku-5-5` で、全プラットフォームで提供が始まっています。AWS、Google Cloud、Microsoft Azure でも使えると書かれていました。

公式が設計の対象に挙げているのは、「大量・コスト重視の作業」です。

- 要約
- コンパクション（文脈の圧縮）
- データベースへの問い合わせ
- 分類

こうしたリクエストを確実に処理するモデルだそうです。コンパクションは、長くなった作業の文脈を短くまとめ直すことだと理解しています。

コーディングでは、Opus 5.5 や Sonnet 5.5 のサブエージェントとして組み合わせるのが、公式の想定です。最も速いモデルなので、ライブの顧客対応やブラウザ操作のような、速度が要る作業にも向くとあります。

価格は、Haiku 4.5 と比べて、動かすコストが平均で約75%低下したと公式は書いています。単価表は、この記事では扱いません。

Haikuクラスで初めて「effort（努力量）」の調整も付きました。コストを取るか賢さを取るかを選べるそうです。

## ② 学び1：「安い＝弱い」が崩れた

1つ目は、小型モデルは安い代わりに弱い、という見方が通らなくなってきたことです。公式発表の表から2つ拾います。

コンピューター操作の OSWorld 2.1（オフライン部分）です。

- Haiku 5.5：72.4%
- 前世代の Haiku 4.5：15.7%
- GPT-6 Luna：48.9%
- 参考の Sonnet 5.5：83.9%

知識労働の GDPval-AA v2.1 です。

- Haiku 5.5：1620
- Haiku 4.5：735
- GPT-6 Luna：1437
- 参考の Sonnet 5.5：1840

前の世代と比べると、OSWorld は15.7%から72.4%へ、4倍以上になっています（これは僕の割り算です）。GDPval-AA も、735から1620へ、2倍以上です。それでいて、動かすコストは平均で約75%低下しています。

ここから先は、僕の読みです。要約や分類のような決まった作業に、わざわざ大きいモデルを使う理由は、前より薄くなったのだと思います。

ただ、Sonnet 5.5 のほうが、どちらの表でも上です。「小型が大型に並んだ」のではなく、「小型でも十分な作業が、前よりずっと増えた」のだと読みました。

## ③ 学び2：モデルは「1つに決める」ものから「作業で使い分ける」ものへ

2つ目は、モデルの選び方です。今回の発表で、公式自身が役割分担を前提に書いているのが印象に残りました。

- 複雑なエージェント型コーディングは、Sonnet 5.5 や Opus 5.5 が今も良い選択肢
- コンパクション、要約、サブエージェント作業のような「範囲の狭い作業」は、Haiku 5.5 が最適。以前はコスト面で見送られていた作業にも向く

エージェント型コーディングのベンチマーク Terminal-Bench 4.0 では、Haiku 5.5 が39.2%、Sonnet 5.5 が70.6%です。複雑なコーディングでは大きいモデルが今も大きく上で、公式もそう明記しています。だから「全部を小さいモデルに」ではなく、「作業の重さで分ける」組み立てになるのだと思います。

第3回で [Gemini 4 Neon](https://note.com/chinamaru_1995/n/n218c90af346e) を読んだときも、各社が「ちょうどいい中間」のモデルを置き始めている、と書きました。Haiku 5.5 も、「役割ごとにモデルを並べる」流れの一部に見えます。

僕は今、Claude Code のメインのモデルに Sonnet を指定しています。そのうえで、量のある定型の処理は Haiku に任せています。たとえば次のような作業です。

- Claude Code でのサブエージェント的な処理
- note運営での要約や照合
- 日常の調べもの
- 楽天ルームの商品紹介記事の下書き
- 大量のデータ入力を伴うWeb操作

公式が設計の対象に挙げた用途と、ほぼ重なっていました。「重い作業は Sonnet、量のある定型処理は Haiku」という使い分けは、公式の想定と同じで、僕がすでにやっていることでもあります。

## ④ 学び3：コストが下がっているのは、モデル本体だけではない

3つ目は、同じ発表の中にあった、周辺の変更です。

- **Sonnet 5.5 のキャッシュ読みが半額になりました。** 100万トークンあたり0.20ドルから、0.10ドルです。キャッシュ読みは消費の大きな部分を占めるので、Sonnet 5.5 はエージェント作業の大半で、約20%安くなると書かれています
- **加入者向けに、月額のAPIクレジットができました。** Claude Max は月100ドル、Ultra は月200ドル、Team は最大500ドルをプールできます。APIでエージェントやアプリを作る実験のためのものだそうです

キャッシュは、同じ内容を繰り返し読ませるときの仕組みだと、僕は理解しています。月額のクレジットは、僕が読んだ範囲では、対象が Max・Ultra・Team で、Pro は挙がっていませんでした。

実務のコストは、モデルの単価だけでは決まりません。キャッシュの扱いや契約のプランでも変わります。「どれが安いか」を調べるときは、本体の価格だけで判断しないようにしよう、と思いました。

## ⑤ 正直な留保

いい話に見えたかもしれないので、分かっていないことを書いておきます。

- **ベンチマークの数字は、公式発表のものです。** 僕の作業での実測ではなく、独立した検証でもありません
- **体感として、速い・安いと感じています。** ただ、時間も金額も測っていないので、数字では書きません
- **複雑なコーディングでは、Sonnet 5.5 が大きく上です。** 39.2%と70.6%が、その差です。「小型で全部まかなえる」という話ではありません
- **発表は2026年10月7日で、最新ニュースではありません。**
