# 「APIって何？」で止まった話。専門用語を1つ調べたら、自動化の形が決まった

## 「APIとか、専門用語が分からなくて置いていかれる」と感じていませんか

AIのことを調べていると、「API連携」「プロンプト」「スクリプト」といった言葉が、説明なしにどんどん出てきます。分からない言葉が一つ出ると、そこから先の文章が頭に入ってこなくなる。そして「自分だけ置いていかれているのでは」と不安になる。そんな経験はありませんか。

こんにちは。31歳、AI初心者の筆者です。この「AI初心者の悩み相談室」は、AIや副業、自動化まわりの悩みに、勉強中の立場から、正直に、できるだけ具体的に答えていくシリーズです。先生として教えるのではなく、「自分はこう調べて、こう決めました」をそのままお渡しします。

第2回の悩みは、こちらです。

**「APIとか、専門用語が分からなくて置いていかれる」**

私も、まったく同じところで止まりました。この記事の本文は、AI（Claude Code）が下書きを書き、AI秘書のMuseが事実確認をして、最終確認は人間である私が行っています。

## 私が最初にぶつかった言葉が「API」でした

私は、本業でAIを使えるようになりたくて勉強中です。その練習の場として、noteの運営をAIと一緒に進めています。

その中で、「noteへの投稿も自動化できないだろうか」と考えて調べ始めました。すると、最初にぶつかった言葉がAPIでした。自動化について調べると、必ずと言っていいほど、この言葉が出てくるのです。

正直に言うと、そのときの私は、APIが何なのかをちゃんと説明できませんでした。なんとなく「プログラムを書く人が使う、難しいもの」という印象だけがあり、ここで読むのをやめたくなりました。

でも、投稿の自動化を考えるなら、避けて通れなさそうです。そこで、この言葉を一つだけ、ちゃんと調べてみることにしました。

## 調べて分かったこと：APIは「決まった窓口」

私なりの言葉でまとめると、APIは次のようなものだと理解しました。

**プログラム同士が、決まった窓口を通して、お願いし合うための仕組み**

お店の注文カウンターを思い浮かべると分かりやすいです。

- お客さんは、厨房に勝手に入って料理を作るわけではありません。カウンターで「これをお願いします」と注文します
- 注文できるのは、メニューに載っているものだけです
- 注文の仕方にも決まり（番号で伝える、先に支払う、など）があります
- 注文を受けたお店は、決まった形で料理を渡してくれます

この「カウンター」にあたるのが、APIです。アプリやサービスは、外から中身をいじられると困ります。だから、お願いできることと、お願いの仕方を決めた窓口を用意しておく。人間がスマホで操作する画面とは別に、プログラムがお願いするための窓口を用意しておく、というイメージです。

ただ、比喩だけで終わると、結局「で、それが自動化と何の関係があるの？」が残ります。そこを、もう一歩だけ書きます。

## だから、自動化と関係してくる

自動化とは、人間が画面で行っている操作を、プログラムに代わりにやってもらうことです。

たとえば、noteに記事を投稿するとき、人間はブラウザで画面を開いて、文章を貼って、ボタンを押します。これをプログラムに任せるには、「この文章を、私のnoteに投稿してください」と、プログラムがお願いできる窓口が必要です。その窓口がAPIです。

つまり、こう言えます。

- 窓口（API）がある → プログラムが代わりにお願いできる → 自動化しやすい
- 窓口（API）がない → プログラムがお願いする先がない → 自動化しにくい

「APIがあるかどうか」は、自動化できる範囲を左右するのだと分かりました。「APIがあるかどうかで、自動化のしやすさが変わる」と言われる意味が、ここでようやくつながりました。

## 実例：noteのAPIを調べたら、設計が決まった

では、noteにはその窓口があるのか。私は公式ヘルプで確認しました（2026年11月16日確認）。

- noteのAPIは、note proを利用する法人向けに提供され、対応するサービスと連携して使う形で案内されています
- 自社サービスへの導入は、「ソリューションパートナー」契約の事業者が対象とされています
- 個人アカウントが、自作の仕組みから投稿できる公式APIの案内は、私は見つけられませんでした

つまり、個人の私が使える公式の窓口は、少なくとも案内されていませんでした。窓口が個人向けには開いていないのなら、「完全自動で投稿する仕組み」を前提に組むのは無理があります。

そこで私は、設計を次のように決めました。

**下書きまでは自動、公開は人間が行う。**

AIが下書きを作り、人間（私）が確認して、公開は自分の手で行う。ネットには、公式ではない方法で自動投稿する話も出てきます。ただ、公式に案内されていないやり方を前提にすると、あとで使えなくなったり、アカウントに影響が出たりする心配があります。だから私は、そういう方法は使わない方針にしました。

結果として、これは悪くない設計だったと感じています。AIが書いた文章は、公開前に人間が必ず目を通せるからです。

用語を1つ理解したことで、「何を自動にして、何を人間がやるか」が決まりました。これが、今回いちばんお伝えしたいことです。

## ほかにも、つまずいた言葉を2つ

APIのほかにも、私が最初に引っかかった言葉が2つあります。どちらも、実際にやっていることと地続きのものだけを書きます。

**プロンプト**

AIへの指示文のことです。私の場合、Claude Codeに「こういう悩みについて、こういう構成で下書きを書いてください」と伝える文章が、プロンプトにあたります。難しい言葉ですが、言い換えれば「AIへのお願いの書き方」です。今回の記事のように、AIに下書きをお願いするときは、ここに「こんな文体で」「この事実だけを使って」といった条件も書きます。

**プルリクエスト（PR）**

GitHubで原稿を管理していると出てくる言葉です。「この変更を取り込んでもいいですか」という確認依頼のことで、私の場合は、AIが書いた原稿を、私が確認してから取り込むための関門になっています。取り込む（マージする）かどうかを決めるのは、人間の私です。

言葉の意味を知ると、「AIが勝手に何かをしている」のではなく、「人間が確認する場所がどこにあるか」が見えてきます。専門用語は、仕組みを理解するための手がかりでもあるのだと思いました。

## できること／できないことの線引き

ここまでの経験から、「分かったこと」と「まだ分からないこと」を、正直に分けてみます。

**分かったこと・できたこと**

- APIを「プログラム同士が、決まった窓口でお願いし合う仕組み」と、自分の言葉で説明できるようになりました
- noteについては、個人が使える公式APIの案内を見つけられなかったので、「下書きまで自動、公開は人間」の半自動にしました

**まだ分からないこと・できていないこと**

- APIの中身（どんな形でお願いを送るのか、など）は、まだ詳しく分かりません。今回理解したのは、「窓口」という考え方までです
- noteの法人向けAPIの具体的な使い方や、契約の条件は、私は確認できていません
- 「分からない言葉は、調べれば必ず分かる」と言えるほど、私はまだ慣れていません。今回はうまく進んだ、という話にとどまります

現在地も、数字でお伝えしておきます（2026年11月17日時点の実測です）。

- 売上：0円
- X（@kekun_ai）：フォロワーは0からのスタートです

まだ「うまくいっている」と言える段階ではありません。「これをやれば稼げます」とも言えません。言えるのは、「言葉を1つ調べたら、設計が決まった」ということまでです。

## 今日からできる小さな一歩

もし今日、10分だけ時間があるなら、次のことを試してみてください。

1. 最近、読んでいて引っかかった言葉を1つ選ぶ（今日は1つだけで大丈夫です）
2. その言葉の意味を、公式の説明やヘルプなど、できるだけ元の情報で調べる
3. 「つまり〇〇ということ」と、自分の言葉で1行にまとめてメモする

大切なのは、一度に全部の用語を覚えようとしないことです。分からない言葉が出てきたら、その場で1つだけ調べる。これを繰り返すだけでも、置いていかれる感覚は少しずつ小さくなっていくと、私は感じています。
