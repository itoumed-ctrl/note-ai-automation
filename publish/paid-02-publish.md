# AIの答えを鵜呑みにしない事実確認の5つの道具

## 1. この記事で手に入るもの

こんにちは。31歳、AI初心者の筆者です。本業でAIを使えるようになりたくて、勉強しながらnoteの運営をAIと一緒に進めています。「AI自動化の実録」シリーズの、有料記事の2本目です。

AIの答えは、きちんとした文章で返ってきます。だから数字や日付が間違っていても、読んだだけでは気づけません。僕もずっと不安でした。

この記事を読み終えると、AIが書いた文章の事実を確かめる手順が、「キット」として手元に揃います。

- 確かめる作業を5つの道具に分けた、全体の流れ
- 数字、日付、固有名詞などの種類別チェックリスト
- そのまま使えるテンプレート3点の全文（事実の箱、AIへの依頼文、公開前チェックリスト）

「AIに任せれば事実確認は要らなくなる」という話ではありません。AIが書いたものを人間が確かめる。その確かめ方を毎回同じ手順にして、ファイルに残しておく、という話です。

## 2. 前提と範囲

相談室の第5回（無料）で、確かめ方の考え方を公開しました。数字は自分で計算して報道と照合する、大事な事実は一次情報で見る、公開前に実測と照合する、の3つです。この記事は、その実践版です。考え方を、手順とチェックリストとテンプレート全文にしました。第5回を読んでいなくても使えます。

僕のnote運営は、Claude Codeが執筆し、AI秘書のMuseが事実確認をして、公開は人間の僕が行う分担です。執筆の前には「事実の箱」を作り、確認済みの事実だけを入れています。この記事のキットは、その運用を取り出したものです。

先に断っておくと、専門家の検証方法ではありません。初心者の僕が毎日の運用で使っているやり方の記録です。このキットで間違いがなくなる、とも言えません。

道具といっても、特別なソフトは使いません。テキストのファイルと、チェックリストと、確認の順番だけで回せます。

## 4. 5つの道具と、付録テンプレート3点

事実確認のキットは、5つの道具でできています。

1. 事実の箱：確認済みの事実だけを集めて、執筆の材料にする
2. 種類別チェックリスト：数字、日付と曜日、固有名詞、URLと出典、自分の現在地を、種類ごとに確かめる
3. 2ソース照合と検算：数字を別の情報源と突き合わせ、計算で出せる数字は計算し直す
4. 「未確認」と書くルール：確認できないものを、推測で埋めずに、そう書く
5. 公開前の矛盾チェック：公開前に実測値を取り、本文の全記述と照合する

付録には、テンプレート3点の全文を載せています。

- A. 事実の箱フォーマット
- B. AIに事実確認を頼む依頼文
- C. 公開前チェックリスト

## 5. 道具1 事実の箱

事実の箱は、記事に使ってよい事実だけを集めたメモです。執筆を頼む前に作ります。

僕は執筆担当に、毎回こう指示しています。

「箱の中の事実だけを使う。書かれていない体験や数字を作らない。」

この一文があると、AIが空白を埋めようとして数字を作るのを防げます。逆に言うと、箱に入っていない事実は、記事に書けません。

書いている途中で新しい事実が必要になったときも、本文に直接足しません。いったん箱に戻って確認し、入れてから書きます。この順番を崩さないのが、箱を使うときの約束です。

### 作り方

1. 記事に使いたい事実を、1件ずつ確認する
2. 確認できたものだけを、箱に入れる
3. 確認できなかったものは、箱の「未確認」の欄に分けて置く（道具4で使います）
4. 執筆を頼むときに、箱を貼って、上の一文を添える

### 箱に入れる項目

- 内容：事実を一文で
- 数字と単位：単位まで書く
- 誰の発言か：公式発表、報道、筆者の計算、筆者の実測のどれか
- 出典URL
- 確認日
- 状態：確認済み、報道ベース、未確認のどれか

「誰の発言か」を入れるのが、一番大事だと思っています。同じ数字でも、公式が言っているのか、報道が言っているのか、僕が計算したのかで、重みが違います。

### 記入例

形式を見るための一般的な例です。実在のデータではなく、数字は【 】で仮に置いています。実際に使うときは、確認できた値に置き換えてください。

- 内容：ある製品の月額料金
- 数字と単位：月額【◯◯】ドル
- 誰の発言か：公式発表
- 出典URL：【公式の料金ページのURL】
- 確認日：【YYYY-MM-DD（曜日）】
- 状態：確認済み

全項目つきの書式は、付録Aにあります。

## 6. 道具2 種類別チェックリスト

事実は、種類によって見る場所が違います。種類ごとに、何をどう確かめるかを分けました。毎回すべてをやるのではなく、記事に出てくる種類のところだけ使ってください。全部を確かめようとすると、続かなくなります。まずは、記事の中で一番大事な数字や日付から始めるのがおすすめです。

### 数字

- [ ] 単位まで書いてある（ドル、円、％、本など）
- [ ] 元の資料と見比べて、写し間違いがない
- [ ] 計算で出せる数字は、自分で計算し直した
- [ ] 大事な数字は、別の情報源とも突き合わせた（道具3）

### 日付と曜日

- [ ] 日付を一次情報で確認した
- [ ] 曜日まで確認した
- [ ] 米国時間か日本時間かを書いた
- [ ] 「◯月◯日時点」の時点を書いた

ニュース第4回の例だと、取引が始まったのは米国時間2026年11月19日（木）で、市場が引けたのは日本時間の11月20日の朝6:00です。日付だけだと、米国と日本で1日ずれます。

### 固有名詞

- [ ] 会社名、製品名、サービス名、人名を、公式の表記と見比べた
- [ ] 版や型番が必要なものは、版まで確認した

### URLと出典

- [ ] URLを実際に開いて、書いてある内容を確かめた
- [ ] 出典URLと確認日を、原稿の末尾メモに残した
- [ ] 一次情報（公式）か、報道やまとめか、書き分けた

### 自分の現在地（変わり続ける数字）

公開本数、フォロワー数、スキ数、売上のように、日がたつと変わる数字です。

- [ ] 記憶やAIの下書きではなく、実測値を取りに行った
- [ ] 「◯月◯日時点」を添えた
- [ ] 取れていない数字は「未計測」と書いた
- [ ] 古い現在地が、ほかの箇所に残っていない（道具5）

## 7. 道具3 2ソース照合と検算

### 手順

1. 数字ごとに、誰が言っている数字かを書く
2. 別系統の情報源を探す（データと報道、公式と報道など）
3. 突き合わせて、一致したものは「2ソース」、できなかったものは「1ソース」と箱に記録する
4. パーセントなどの派生数字は、元の数字から計算し直す

ポイントは、一致しなかったものを隠さないことです。1ソースのままの数字は、そう書いて出します。

2ソースと数えるときは、本当に別系統かを見ます。片方がもう片方の記事を引用しているだけなら、元をたどれば1ソースです。同じ元の数字を見ているだけでは、突き合わせたことになりません。

### 実例：ニュース第4回の株価

Anthropicの上場初日の株価です。公開価格は83ドル、初値は111.50ドル、終値は97.17ドルでした。

照合では、Finnhubの株価データと、Reutersなどの報道を突き合わせました。初値と高値は、報道とも一致しました。安値と終値は、Finnhubの数字だけです。僕が証券会社の取引画面で見た数字でもありません。記事には、そのとおりに書きました。

検算は、記事に書く値上がり率です。

- 初値：（111.50−83）÷ 83 ＝ 28.5 ÷ 83 ≒ 0.343 → +34.3％
- 終値：（97.17−83）÷ 83 ＝ 14.17 ÷ 83 ≒ 0.171 → +17.1％

記事の数字と一致しました。

注意点があります。検算が合っても、元の数字が正しいことの証明にはなりません。合ったのは、計算の中での話です。元の数字の確かさは、照合のほうで見ます。

## 8. 道具4 「未確認」と書くルール

確認できなかったとき、推測で埋めるのが一番危ない書き方です。僕は次の3つの型を使っています。

- 型1 未確認と明記する：「◯◯は、公式では確認できませんでした」と書く
- 型2 報道ベースと断る：「報道によると◯◯です。公式では確かめていないので、報道ベースの情報です」と書く
- 型3 数字を出さない：確認できない数字は、書かない。必要なら「未計測」と書く

型の選び方は、順番に考えると迷いません。公式で確認できたなら、そのまま書きます。公式では確認できないが報道がある、なら型2です。報道もない、あるいは情報源同士が食い違っている、なら型1か型3にします。

### 実例：ニュース第3回

Gemini 4 Neonの回では、Intelligence Indexの61点を、Googleの発表の中で読んだ数字として書きました。独立機関のページでは確認できていませんし、ほかのモデルの点数と同じ条件で測られたのかも分かりません。これも本文に書きました。各モデルの日付も、報道ベースと断っています。

### 実例：ニュース第5回

対象プランについて、公式の情報同士が食い違っているという指摘がありました。発表ではPlus、Pro、Ultraとされている一方で、サポート文書にはProとUltraだけと読める箇所がある、という内容です。公式ブログの本文には、対象プランも動作環境も書かれていませんでした。僕はどちらかに決めず、「報道ベース」として保留にしました。

見たものは「見た」、見ていないものは「見ていない」と書く。それだけで、読む人は受け取り方を決められます。

## 9. 道具5 公開前の矛盾チェック

公開前の朝に、記事の中身と今の実測が食い違っていないかを見ます。

### 手順

1. 実測値を取りに行く（公開本数、売上、フォロワー数、スキ数）
2. 本文の全記述を、実測値と照合する
3. 食い違いを直す
4. 保存し直して、直した版を開き直して確認する

2の「全記述」が肝心です。数字の欄だけでなく、「今夜公開予定」「◯月◯日時点」のような時点の書き方や、日付、冒頭からまとめまでの文章全体を見ます。

古い記述は、同じ内容が冒頭、本文、まとめ、末尾メモと、何か所にも散らばって残りやすいものです。目で追うだけだと拾い残すので、「時点」「本」「円」「今夜」「明日」といった言葉で本文を検索して、ヒットした箇所を1つずつ実測と見比べるのも手です。

### 成功例：2026年11月21日の朝

この朝、その日に公開予定だった3本を照合しました。直した箇所は、合計15か所です。

- 相談室 第6回：2か所
- 実録の無料記事：7か所
- 有料記事 第1回：6か所

すべて、「2026年11月16日時点・公開0本」という古い現在地が残っていたものでした。書いた時点では正しかった現在地が、公開日には古くなっていたわけです。

### 失敗例：相談室 第5回

第5回では、公開前のチェックで2か所の古い記述を見逃したまま公開してしまいました。現在地が「公開7本・2026年11月19日時点」のまま残った箇所と、記事の日付の食い違いです。

それまでのチェックは、数字が中心でした。この失敗を受けて、チェックの範囲を「数字だけ」から「文章の事実全体」に広げました。数字が合っていても、文章の中の日付や時点の言い方が古いことがあります。公開前に気づけなかった、という事実は変わりません。だからこそ、失敗した形のまま書き残しています。

## 10. 毎日の回し方と、できていないこと

回す順番は、次のとおりです。

1. 書く前：事実の箱を作る（道具1）
2. 書いたあと：種類別チェックリストで確かめる（道具2）。数字は2ソース照合と検算をする（道具3）
3. 確認できないもの：「未確認」「報道ベース」と書く（道具4）
4. 公開前の朝：矛盾チェックをする（道具5）

2と3は、Museに頼めます。依頼文は付録Bです。ただ、Museの「確認しました」という報告だけで済ませず、出典URLと確認日が付いていることを、人間の僕が見ます。

5つを一度に始める必要はありません。重い作業に感じたら、道具1の事実の箱と、道具5の矛盾チェックの2つから始めてください。この2つだけでも、「書いてある事実の出どころが分かる」「古い現在地が残らない」という状態に近づけます。残りの3つは、記事に数字や日付が増えてきたときに足せば十分です。

できていないことも書いておきます。

- 意見や感想は、確かめる対象ではありません。正解を確かめる方法が、そもそもないからです
- 確認に時間がかかります。そのため、大事なところから確かめています
- このキットで事実のミスがどれだけ減ったかは、数えていません

数字が動いたときは、動いた数字をそのまま書きます。動かなかったときは、動かなかったと書きます。

### B. fact-check-request.md（AIに事実確認を頼む依頼文）

```
あなたは、記事の事実確認の担当です。下の原稿を読んで、事実を確認してください。

【対象】【articles/◯◯.md】

- 食い違い・注意点：
- 原稿の直し案：直すかどうかは人間が決める

```
